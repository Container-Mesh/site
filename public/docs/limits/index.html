Limits

ContainerMesh connects containers on this Mac. These are the limits of that connection.

One shared network

Every eligible running container joins one shared network. Containers from different projects can reach each other on all ports. While ContainerMesh is connected, programs on your Mac can reach every port of every connected container. This is shared local connectivity. It is not a separate network for each project.

Pause and Quit stop ContainerMesh. They leave the containers on that network, so those containers can still reach each other. Turning a name off only hides the name. To keep a container off the network, create it with the label io.containermesh.enabled=false.

A container that uses the host network, no network, or another container's network stays off.

Who can change the connection

Any program running as the logged-in user can ask ContainerMesh for a free name ending in .test, or for one private address range from /16 to /30.

VPNs

A VPN that sends all traffic can stay on. ContainerMesh adds its own route beside that VPN. If a route already covers the same private addresses, ContainerMesh refuses to connect. If such a route appears while ContainerMesh is connected, ContainerMesh stops.

Which Docker

ContainerMesh accepts a Docker context whose address is a local socket, written as unix://. It checks that when the connection starts, and it does not keep checking. A socket of that form can still be forwarded to a Docker engine on another machine.

Logs

Copy logs copies the text as ContainerMesh has it. Nothing is removed. The text can include container names and folders in your home directory. Read it before you paste it into a bug report.

The built app

The app contains the revision it was built from, and the names of the modules used in that build.

Open advisories

Two dependency advisories stay open. Neither is part of the app you run. The build stops if either module is imported.
